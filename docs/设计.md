# 摄影素材工作流

## 原始素材预处理

### 照片文件重命名

对于原始照片，我会将素材拷贝到本地的 `Photograph-local` 目录下，并按照日期（例如 250101）和相册名称进行重命名，这样可以方便后续的管理和查找。

文件结构如下：

```bash
./cache/Photograph-local
└── YYMMDD-相册名称
    ├── DSC08656.ARW
    ├── DSC08657.ARW
    └── ...
```

这些照片需要根据 `YYMMDD-相册名称` 进行重命名，但是这些原始素材可以读取出拍摄日期和时间，因此我会使用 python 并借助 `exiftool` 库来读取 exif 数据，并将文件重命名为 `YYMMDD-相册名称-时间.ARW` 的格式。

例如 `DSC08656.ARW` 可以读取到拍摄日期和时间，然后重命名为 `YYMMDD-相册名称-时间.ARW` 的格式。

这是索尼的格式，你可以从 exif 数据中获取到厂商和型号信息。

我需要定义一个专用于重命名索尼 RAW 文件的类

```python
class BaseTask(ABC):
    """任务基类"""

    @abstractmethod
    def generate(self) -> None:
        """生成任务方法，子类需要实现此方法"""
        raise NotImplementedError("Subclasses must implement this method")

    @abstractmethod
    def description(self) -> str:
        """返回任务描述、，模拟执行时使用"""
        raise NotImplementedError("Subclasses must implement this method")

    @abstractmethod
    def execute(self, dry_run: bool = True) -> None:
        """
        执行当前任务
        :param dry_run: 是否为模拟执行
        """
        raise NotImplementedError("Subclasses must implement this method")


class TaskManager:
    """任务管理器，用于注册和管理处理器任务"""

    task_list: typing.List[BaseTask]
    """任务列表，存储所有注册的处理器"""

    def __init__(self):
        self.task_list = []


class RenameSonyRawPhotoTask(BaseTask):
    """索尼相机原始照片任务，用于处理单个 .ARW 文件及其对应的 .XMP 文件"""

    file_path: Path
    """文件路径"""

    album_name: str
    """相册名称"""
```

## 摄影元数据插件系统

### 背景

照片重命名任务需要从不同格式中读取拍摄时间。早期实现直接在 `RenameRawPhotoTask` 中根据扩展名分支处理 `exifread`、`pillow_heif`、`piexif` 等读取细节。随着 RAW、JPEG、HEIF、TIFF、视频、厂商专有格式和附属文件增多，任务类会持续膨胀，也会让新增格式时更容易影响已有流程。

插件系统的目标是拆分职责：任务只负责扫描目录、生成重命名任务和执行重命名；插件只负责根据文件路径读取拍摄时间。

### 插件契约

元数据插件基类为 `PhotoMetadataPlugin`。每个插件必须声明：

- `name`：插件唯一名称，例如 `builtin.exif-raw`。
- `version`：插件版本，用于后续兼容性追踪。
- `extensions`：插件支持的主文件扩展名，例如 `{".arw", ".dng"}`。
- `sidecar_extensions`：主文件对应的附属文件扩展名，例如 `{".xmp", ".acr"}`。
- `read_original_datetime(file_path) -> str`：读取拍摄时间，返回 `YYYY:MM:DD HH:MM:SS`。

插件不得直接重命名、移动、删除或写入照片文件。文件名生成、确认和执行仍由任务层统一负责。

### 内置插件

当前内置插件包括：

- `builtin.exif-raw`：处理 `.arw`、`.dng`、`.raf` 等 RAW 文件，附带 `.xmp` 和 `.acr`。
- `builtin.exif-image`：处理 `.jpg`、`.jpeg`、`.tif`、`.tiff`。
- `builtin.heif`：处理 `.heif`、`.heic`、`.hif`。

`.xmp` 和 `.acr` 作为附属文件单独扫描到时会被忽略；只有遇到同名主文件时才会跟随主文件一起重命名。

### 插件加载方式

插件注册表按扩展名查找插件，并拒绝重复扩展名，避免两个插件同时声明处理同一种主文件。

支持三种加载方式：

- 内置插件：默认启用，覆盖常用照片格式。
- 显式模块：通过 `metadata_plugin_modules` 配置模块路径。模块需暴露 `PLUGIN`、`PLUGINS` 或 `get_plugins()`。
- Python entry points：通过 `load_entry_point_plugins=True` 显式启用，默认 group 为 `a_bag_of_scripts.photograph.metadata_plugins`。

entry points 默认关闭，避免自动加载未知第三方代码。需要使用第三方插件时，应在配置中显式开启。

### 安全边界

插件只读元数据，不拥有文件操作权限。任务层仍负责以下安全规则：

- sidecar 文件只跟随主文件，不单独生成重命名任务。
- 未注册且未忽略的扩展名直接报错，避免静默漏处理。
- 重复扩展名注册直接失败。
- 测试必须使用临时目录模拟照片文件，不能依赖真实 iCloud 或本地照片目录。

后续如果引入更复杂的安全机制，例如 manifest、hash 校验、禁止覆盖和回滚，也必须保持在任务层实现，插件不得绕过这些保护。

### 扩展示例

项目内插件可以定义为：

```python
from modules.photograph.metadata_plugins import PhotoMetadataPlugin


class MyFormatPlugin(PhotoMetadataPlugin):
    def read_original_datetime(self, file_path: str) -> str:
        return "2025:01:01 12:00:00"


PLUGIN = MyFormatPlugin(name="local.my-format", extensions=[".foo"])
```

然后通过 `metadata_plugin_modules=["my_plugin_module"]` 显式加载。
